# ADR 0001: AxonLLM v0.3 Product Boundary

- Status: Accepted
- Date: 2026-08-13

## Context

AxonLLM currently combines an LLM routing data plane, an enterprise control
plane, identity, governed Athena access, and multiple AWS deployment products.
Treating all of those capabilities as one release boundary has made it hard to
state what the open-source product is and what must be certified before a
public release.

The v0.3 release needs one product definition that works in a Python process,
as a standalone gateway, and on AgentCore Runtime without maintaining separate
routing implementations.

## Decision

AxonLLM is an open-source LLM gateway with two mandatory logical components:

1. A router data plane that normalizes provider APIs, selects provider routes,
   retries and falls back, streams responses, and emits usage and routing
   telemetry.
2. A control plane that manages provider and model configuration, virtual
   keys, policies, budgets, usage, audit history, and configuration
   publication.

The control plane is mandatory product functionality. It does not need to be a
separate process in every deployment. A single-node standalone installation
may co-locate the control plane and router, but inference must route from a
local versioned configuration snapshot rather than synchronously consulting
the control plane on every request.

One router core will support three delivery modes:

- Embedded Python: applications import the public `axonllm` package.
- Standalone: an OpenAI-compatible HTTP server and the control plane run as a
  supported self-hosted installation.
- AgentCore: an ARM64 HTTP Runtime adapter hosts only the router data plane;
  the mandatory control plane runs separately and publishes configuration to
  it.

The existing `src.gateway` namespace remains an internal implementation detail
during v0.3 migration. New consumers use the stable `axonllm` namespace.

## Public Beta Scope

The v0.3 public beta includes:

- Multi-provider model mappings and provider fallback.
- Process-local adaptive selection among concrete routes for a provider.
- Chat Completions, Responses, Embeddings, Models, health, and readiness
  compatibility endpoints.
- Streaming, tool transport, consistent errors, and usage accounting.
- A mandatory control-plane experience for configuration, keys, policies,
  budgets, telemetry, and audit.
- A Python package, multi-architecture standalone image, and ARM64 AgentCore
  image using the same router core.

## Deferred

The following work does not block the v0.3 public beta:

- Fleet-wide adaptive load balancing and shared provider-capacity learning.
- Athena query execution.
- Agent loops, tools, memory, and application workflows.
- Ostiari integration.
- Multi-region production certification.
- SCIM and SAML production certification.
- A Go or Rust data-plane rewrite.

Until the fleet milestone is complete, the supported claim is
**process-local adaptive route selection with multi-provider fallback**, not
fleet-wide adaptive load balancing.

## Consequences

- AgentCore becomes a hosting adapter, not a separate AxonLLM product.
- Router code must not construct identity, Athena, admin UI, or persistence
  services merely to perform an embedded completion.
- Control-plane outages do not stop an already configured router; routers use
  the last-known-good signed snapshot and report degraded synchronization.
- Standalone and AgentCore releases must pass the same routing conformance
  suite.
- Features outside this boundary can remain in the repository while they are
  separated, but they cannot expand the v0.3 release gate.
